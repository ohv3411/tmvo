# tmvo.ru — от демо к рабочему магазину

Три этапа. Каждый следующий не ломает предыдущий: фронтенд один и тот же, меняется только `apiMode` в `assets/js/config.js`.

| Этап | Что получаем | Что нужно | Срок |
|---|---|---|---|
| **0. Демо (сейчас)** | Сайт, каталог, корзина, заказы, админка — всё в браузере. Заказы видит только тот, кто их оформил. | Ничего | готово |
| **1. Без базы** | Каждая заявка и заказ сразу приходят менеджерам в Telegram. Сайт на GitHub Pages или любом хостинге. | Telegram-бот, облачная функция | 1 день |
| **2. С базой** | Заказы хранятся на сервере, общая админка для всех менеджеров, журнал согласий, письма. | Сервер в РФ, PostgreSQL, разработчик | 2–4 недели |
| **3. Онлайн-оплата** | СБП и карта через ЮKassa, статус «Оплачен» автоматически, чеки 54-ФЗ. | Договор с ЮKassa | 1 неделя после этапа 2 |

---

## Этап 1. Работающая система без базы

**Как работает.** Покупатель оформляет заказ как сейчас. Сайт отправляет его на одну маленькую функцию (`server-lite/index.js`), а она пересылает сообщение в Telegram-группу менеджеров: номер, телефон, товары, адрес, способ оплаты. Ничего не хранится на сервере — история заказов живёт в чате Telegram.

**Что нужно от вас (по порядку):**
1. **Telegram-бот.** В Telegram открыть @BotFather → `/newbot` → получить токен.
2. **Группа менеджеров.** Создать группу, добавить туда бота и менеджеров. Узнать id группы (например, через @getmyid_bot — добавить в группу на минуту).
3. **Облачная функция.** Аккаунт в Yandex Cloud (серверы в РФ) → Cloud Functions → создать функцию, среда Node.js 18, вставить `server-lite/index.js`, точка входа `index.handler`. Переменные окружения: `BOT_TOKEN`, `CHAT_ID`, `ALLOWED_ORIGIN` (адрес сайта). Сделать функцию публичной. Стоимость при сотнях заявок в месяц — в пределах бесплатного лимита.
4. **Включить на сайте.** В `assets/js/config.js`: `apiMode: "lite"`, `liteEndpoint: "<адрес функции>"`. Залить сайт.
5. **Проверить.** Оформить быстрый заказ, полный заказ и «Заказать звонок» — три сообщения должны прийти в группу.

**Ограничения этапа 1:**
- Админка `/admin/` показывает только заказы своего браузера — работать с заказами менеджеры будут в Telegram.
- Цены в сообщении считаются в браузере покупателя — менеджер сверяет их по прайсу при звонке.
- Журнал согласий — в истории чата (в сообщении есть отметка о согласии). Для полного соответствия 152-ФЗ нужен этап 2.
- Telegram — зарубежный сервис: передача телефона покупателя в Telegram — трансграничная передача. Это предусмотрено п. 7 политики конфиденциальности, но лучше перейти на этап 2.

## Этап 2. База данных

**Что делает разработчик:**
1. Сервер в РФ (Timeweb, Beget, Selectel, Yandex Cloud) + PostgreSQL.
2. Создаёт таблицы из `db/schema.sql` и загружает каталог из `data/catalog.json` (категории → `categories`, товары → `products`, размеры → `product_variants`, фото → `product_images`).
3. Реализует API из `TECH_SPEC.md`, раздел 5 (публичная часть) и раздел 10 (админка: `/api/admin/login`, `/api/admin/orders`, `/api/admin/callbacks`). Формат ответов — как в демо, фронтенд и админка уже готовы.
4. Письма магазину и покупателю, Telegram-уведомления (можно взять текст из `server-lite`).
5. Ставит `apiMode: "api"`. Пароль `test/test` больше не действует: вход в `/admin/` — по пользователям из таблицы `admin_users`.

**Модель данных (коротко):**
```
categories 1─* products 1─* product_variants   (размер и цена)
                       1─* product_images     (главное фото и галерея)
                       1─* promotions         (скидка %, период)
orders 1─* order_items      (цена на момент заказа)
       1─* order_history    (кто и что менял)
       1─* consents         (журнал согласий, 152-ФЗ)
       1─* payments         (этап 3)
callbacks ── consents
admin_users 1─* admin_sessions, orders.manager_id
```

Обновление каталога: тот же Excel → `tools/build_data.py` → `data/catalog.json` → импорт в базу скриптом разработчика.

## Этап 3. Онлайн-оплата

По `TECH_SPEC.md`, раздел 9: договор с ЮKassa → `shopId` и секретный ключ на сервере → создание платежа с выбранным способом (СБП показывает QR сразу) → webhook об оплате → статус «Оплачен» → чек 54-ФЗ. На сайте включить способы `sbp` и `bank_card` в `config.js`.

## Фото товаров: что выгрузить из Битрикс

Сейчас фото есть у 34 из 97 товаров. Присланная выгрузка `export_file_881689.csv` содержит только поле `IP_PROP34` — общие фото тканей, одинаковые у всех матрасов, главного фото в ней нет.

**Как выгрузить главные фото:** Магазин → Каталог товаров → Экспорт → CSV (или Контент → Инфоблоки → Экспорт CSV) для инфоблока «Каталог».
1. В полях отметить: **Название (IE_NAME)**, **Символьный код (IE_CODE)**, **Картинка для анонса (IE_PREVIEW_PICTURE)**, **Детальная картинка (IE_DETAIL_PICTURE)** и **Дополнительные фото (IP_PROP34)**.
2. Включить выгрузку файлов (картинки сохранятся в папку `export_file_…_files/iblock/…`).
3. Заархивировать CSV вместе с папкой файлов и прислать одним zip.

По символьному коду (например, `matras-zevs`) фото автоматически привяжутся к товарам сайта.
