# tmvo.ru — сайт и техническое задание на серверную часть

Версия 2.0 (октябрь 2026). Многостраничный статический сайт интернет-магазина + описание того, что должен сделать сервер, чтобы сайт принимал реальные заказы и оплату.

Сейчас сайт работает в режиме **демо** (`assets/js/config.js → apiMode: "mock"`): каталог, фильтры, карточки товаров, акции, корзина, избранное, быстрый заказ, оформление по шагам и страница заказа работают полностью, но заказы хранятся только в браузере. Чтобы сайт стал рабочим, сервер реализует API из раздела 5 и в config.js ставится `apiMode: "api"`.

### 3.2. Жёсткость
С версии каталога 7.0 у товаров с разной жёсткостью сторон «Категория: Жёсткость» содержит оба значения через «; » (например «Мягкий; Жесткий»). Фильтр «Мягкие» находит товар, если хотя бы одна сторона мягкая; «Разная жёсткость сторон» — по полю «Категория: Разносторонний» = Да.

### 3.3. Скидки
Механизм заложен (процент и период `[from, to)`, округление вверх до 10 ₽, функция `TMVO_PRICE.priceOf` в api.js — сервер обязан считать так же), но сейчас выключен: цены берутся из каталога, скидки не применяются.

## 4. Сценарии

### 4.1. Быстрый заказ
1. Покупатель на карточке товара (или в корзине) нажимает «Быстрый заказ».
2. Вводит телефон, по желанию имя, ставит 2 галочки согласия.
3. Фронтенд → `POST /api/orders/quick`. Сервер создаёт заказ `type=quick`, `status=new`, сохраняет согласие, отправляет письмо магазину.
4. Покупатель видит «Заявка № N принята». Менеджер перезванивает и доводит заказ в админке.

### 4.2. Полное оформление
| Шаг | Что вводит покупатель | Запрос | Что делает сервер |
|---|---|---|---|
| 1. Контакты | Телефон + 2 согласия | `POST /api/orders` | Создаёт **черновик** (`status=draft`), сохраняет согласие, возвращает `id` и `token`. Отправляет письмо магазину «Незавершённое оформление» |
| 2. Получатель | Имя (обяз.), e-mail, комментарий | `PATCH /api/orders/{id}` | Обновляет черновик |
| 3. Получение | Курьер: город, улица и дом, этаж, квартира, лифт | `PATCH /api/orders/{id}` | Обновляет черновик |
| 4. Оплата | Способ оплаты | `PATCH /api/orders/{id}` | Проверяет, что способ включён |
| 5. Проверка | Галочка оферты (обяз.), рассылка (по желанию) | `POST /api/orders/{id}/confirm` | `status=new` (или `awaiting_payment` для онлайн-оплаты). Письмо магазину «Новый заказ», письмо покупателю |
| — | — | `GET /api/orders/{id}` | Страница заказа |

Каждый `PATCH` дополнительно присылает актуальную корзину `items` — сервер пересчитывает позиции и сумму.

Если покупатель ушёл после шага 1, у магазина уже есть телефон и состав корзины (черновик + письмо).

## 5. API

### 5.0. Общие правила
- Базовый адрес: `config.js → apiBase` (по умолчанию `/api`). Формат — JSON, кодировка UTF-8.
- Доступ к конкретному заказу — только по паре `id` + `token` (`?token=...`). `token` — случайная строка не короче 32 символов, генерируется сервером. Заказы без токена не отдаются.
- Ошибка — HTTP 4xx/5xx и тело:
  ```json
  { "error": "bad_phone", "message": "Проверьте номер телефона" }
  ```
  `message` фронтенд показывает покупателю как есть.
- Коды ошибок, которые фронтенд ожидает: `bad_phone`, `consent_required`, `empty_cart`, `bad_item`, `bad_name`, `bad_delivery`, `bad_payment`, `offer_required`, `locked`, `not_found`, `rate_limited`.
- Объект заказа в ответах (поле `history` наружу не отдаётся):
  ```json
  {
    "id": "o1047", "number": 1047, "token": "…", "type": "full", "status": "new",
    "created_at": "2026-10-03T12:41:00+03:00", "updated_at": "…",
    "customer": { "phone": "+79001234567", "name": "Роман", "email": "", "comment": "" },
    "items": [ { "product_id": "germes", "name": "Гермес", "category": "matrasy",
                 "width": 160, "length": 200, "qty": 1, "price": 40560, "sum": 40560 } ],
    "total": 40560,
    "delivery": { "method": "courier", "city": "Москва", "street": "Ленинский проспект, д 45",
                  "floor": "5", "flat": "12", "lift": true },
    "payment": { "method": "cash", "status": "not_paid" },
    "offer_accepted": true, "marketing": false
  }
  ```

### 5.1. `GET /api/catalog`
Необязательный: сейчас фронтенд берёт каталог из `data/catalog.js`. Если сервер отдаёт каталог сам — формат как в `data/catalog.json`, а строку `<script src="data/catalog.js">` из `index.html` можно убрать.

### 5.2. `POST /api/orders/quick` — быстрый заказ
```json
{
  "phone": "+7 (900) 123-45-67",
  "name": "Роман",
  "items": [ { "product_id": "germes", "width": 160, "length": 200, "qty": 1 } ],
  "consents": { "privacy": true, "personal_data": true, "versions": { "privacy": "1.0", "consent": "1.0" } },
  "source": "product"
}
```
`source`: `product` | `cart`. Ответ `201` — объект заказа (`type=quick`, `status=new`).

### 5.3. `POST /api/callback` — заказать звонок
```json
{ "phone": "+7 (900) 123-45-67", "name": "", "consents": { … } }
```
Ответ `200 { "ok": true }`. Сохранить заявку и отправить письмо магазину.

### 5.4. `POST /api/orders` — черновик (шаг 1)
```json
{ "phone": "…", "items": [ … ], "consents": { … }, "source": "checkout" }
```
Ответ `201` — объект заказа с `status=draft`, `id`, `token`.

### 5.5. `PATCH /api/orders/{id}?token=…` — шаги 2–4
Любая комбинация полей:
```json
{
  "items": [ … ],
  "phone": "…", "name": "…", "email": "…", "comment": "…",
  "delivery": { "method": "courier", "city": "…", "street": "…", "floor": "…", "flat": "…", "lift": false },
  "payment_method": "cash"
}
```
Только для `status=draft`, иначе `409 locked`. Ответ — объект заказа.

### 5.6. `POST /api/orders/{id}/confirm?token=…` — подтверждение (шаг 5)
```json
{ "offer_accepted": true, "marketing": false }
```
Сервер проверяет: `offer_accepted=true`, есть имя, доставка, способ оплаты; ещё раз пересчитывает цены. Ставит `status=new` или `awaiting_payment` (если способ оплаты онлайн), записывает в историю, отправляет письма. Повторный вызов для уже подтверждённого заказа возвращает заказ без изменений.

### 5.7. `GET /api/orders/{id}?token=…`
Ответ — объект заказа. Без верного токена — `404`.

### 5.8. `POST /api/orders/{id}/payment?token=…` — онлайн-оплата (позже)
```json
{ "method": "sbp" }
```
Ответ:
```json
{ "payment_id": "2e6f…", "confirmation_url": "https://yoomoney.ru/checkout/…" }
```
Фронтенд сразу переходит по `confirmation_url`. Подробности — раздел 9.

### 5.9. `POST /api/payments/yookassa/webhook` — уведомления ЮKassa (позже)
Вызывается ЮKassa, не фронтендом. Раздел 9.

## 6. Данные

### 6.1. Таблицы (минимум)
- **orders**: `id`, `number` (растущий, с 1001), `token`, `type` (`quick`|`full`), `status`, `customer_phone` (E.164, `+7XXXXXXXXXX`), `customer_name`, `customer_email`, `customer_comment`, `delivery_method`, `delivery_city`, `delivery_street`, `delivery_floor`, `delivery_flat`, `delivery_lift`, `payment_method`, `payment_status` (`not_paid`|`pending`|`paid`|`refunded`), `total`, `offer_accepted`, `marketing`, `manager_comment`, `source`, `created_at`, `updated_at`.
- **order_items**: `order_id`, `product_id`, `name`, `category`, `width`, `length`, `qty`, `price`, `sum` — цена фиксируется на момент заказа.
- **consents** (журнал согласий): `id`, `order_id` или `callback_id`, `phone`, `privacy` (bool), `personal_data` (bool), `privacy_version`, `consent_version`, `form` (`quick`|`checkout`|`callback`), `ip`, `user_agent`, `created_at`. Записи не изменяются и не удаляются вместе с заказом.
- **order_history**: `order_id`, `at`, `actor` (`site`|`manager:<имя>`|`yookassa`), `text`.
- **callbacks**: `id`, `phone`, `name`, `status` (`new`|`done`), `created_at`.
- **payments** (позже): `order_id`, `provider`, `provider_payment_id`, `method`, `amount`, `status`, `raw`, `created_at`.

### 6.2. Статусы заказа
| Код | Название | Когда ставится |
|---|---|---|
| `draft` | Незавершённое оформление | После шага 1, пока покупатель не подтвердил |
| `new` | Новый | Быстрый заказ или подтверждённый полный заказ с оплатой при получении |
| `in_work` | В работе | Менеджер взял заказ |
| `awaiting_payment` | Ожидает оплаты | Подтверждён с онлайн-оплатой, оплаты ещё нет (позже) |
| `paid` | Оплачен | Уведомление ЮKassa (позже) |
| `delivery` | В доставке | Менеджер |
| `done` | Выполнен | Менеджер |
| `canceled` | Отменён | Менеджер; черновики старше N дней — автоматически (по желанию) |

Названия статусов фронтенд берёт из своей таблицы `STATUS` в `app.js` — коды должны совпадать.

## 7. Обязательные проверки на сервере

1. **Цена только с сервера.** Цена и сумма каждой позиции пересчитываются по каталогу (`product_id` + `width` + `length`) с учётом действующей скидки (раздел 3.3). Значения из браузера не принимаются. Количество — от 1 до 20.
2. **Телефон.** Нормализовать в `+7XXXXXXXXXX` (принимать `8…`, `+7…`, с пробелами и скобками). 10 цифр после кода, иначе `bad_phone`.
3. **Согласия.** `consents.privacy === true` и `consents.personal_data === true` на каждой форме (быстрый заказ, звонок, шаг 1), иначе `consent_required`. Записать в журнал согласий с IP и User-Agent.
4. **Оферта** — при подтверждении, иначе `offer_required`.
5. **Способы доставки и оплаты** — только включённые (тот же список, что в `config.js`; на сервере держать свою копию настроек).
6. **Защита от спама.** В формах есть скрытое поле `website` — если оно пришло непустым, тихо отвечать успехом и ничего не сохранять. Ограничение частоты: не больше ~5 заявок с одного IP за 10 минут → `429 rate_limited`.
7. **CSRF.** API принимает только `Content-Type: application/json` и проверяет заголовок `Origin` (только свой домен).
8. **E-mail** — если указан, проверить формат.
9. Длина текстовых полей: имя ≤ 100, комментарий ≤ 1000, адрес ≤ 300 символов.

## 9. Оплата

### 9.1. Сейчас
Включены два способа (`config.js → payment`): `cash` — наличными курьеру, `card_courier` — картой курьеру. Оба офлайн: после подтверждения заказ получает `status=new`, `payment_status=not_paid`; оплату отмечает менеджер в админке при выполнении заказа.

### 9.2. Механизм онлайн-оплаты (заложен, выключен)
Во фронтенде уже есть:
- способы `sbp` и `bank_card` с `online: true, enabled: false`;
- если выбран онлайн-способ — кнопка «Подтвердить и перейти к оплате», после подтверждения вызов `POST /api/orders/{id}/payment` и переход по `confirmation_url`;
- на странице заказа кнопка «Оплатить» для `status=awaiting_payment`.

Что сделать на сервере, чтобы включить:
1. В ЮKassa получить `shopId` и секретный ключ, хранить только на сервере.
2. `POST /api/orders/{id}/payment` создаёт платёж через API ЮKassa (`POST https://api.yookassa.ru/v3/payments`, Basic-авторизация `shopId:secretKey`, заголовок `Idempotence-Key`):
   - `amount` — сумма заказа с сервера;
   - `capture: true`;
   - `confirmation: { type: "redirect", return_url: "https://tmvo.ru/zakaz/?id=<id>&t=<token>" }`;
   - `payment_method_data: { type: "sbp" }` для СБП или `{ type: "bank_card" }` для карты — **тогда покупатель сразу попадает на QR-код или форму карты, без списка способов внутри ЮKassa**;
   - `metadata: { order_id }`, `description: "Заказ № 1047"`;
   - `receipt` — данные для чека, если чеки отправляются через ЮKassa (54-ФЗ).
   Вернуть фронтенду `confirmation.confirmation_url`.
3. Webhook `/api/payments/yookassa/webhook`: события `payment.succeeded` и `payment.canceled`. Перед изменением статуса перепроверить платёж запросом `GET /v3/payments/{id}`. При успехе — `payment_status=paid`, `status=paid`, запись в историю, письмо «Оплачен».
4. Чеки по 54-ФЗ: подключить «Чеки от ЮKassa» или свою онлайн-кассу.
5. В `config.js` поставить `enabled: true` у `sbp` и/или `bank_card`. На сервере — то же.

Сверить параметры с актуальной документацией ЮKassa перед реализацией.

## 10. Админка

Готовая панель: `admin/index.html`. В демо (`mock`/`lite`) вход **test / test** (из config.js — это не защита) и данные из localStorage этого браузера. В режиме `api` панель работает через сервер:

| Запрос | Что делает |
|---|---|
| `POST /api/admin/login` `{login, password}` → `{token}` | Вход. Пароли — хеши в `admin_users`. Токен — в `admin_sessions`, срок 12 ч. |
| `GET /api/admin/orders` → `[order…]` | Все заказы (объект как в 5.0 + `history`, `consents`, `manager_comment`). Заголовок `Authorization: Bearer <token>`. |
| `PATCH /api/admin/orders/{id}` `{status, manager_comment}` | Смена статуса и комментария, запись в `order_history` с логином менеджера. |
| `GET /api/admin/callbacks` → `[callback…]` | Заявки на звонок. |
| `PATCH /api/admin/callbacks/{id}` `{status}` | Отметка «обработана». |

Что видно в панели: вкладки по статусам, метка «Быстрый / Полный», поиск по номеру, телефону и имени, карточка заказа (клиент, товары, получение и оплата, статус, комментарий менеджера, согласия, история), заявки на звонок. Для демо есть кнопка «Добавить 3 примера заказов».

## 11. Продакшен

- **Хостинг.** Сейчас — GitHub Pages (статический сайт). Для рабочего магазина сервер с API нужен на хостинге в России (152-ФЗ, ст. 18, ч. 5), HTTPS обязательно.
- **Адреса.** Ссылки сейчас ведут на `…/index.html`, чтобы сайт работал в подпапке GitHub Pages и с диска. На рабочем сервере поставьте `CLEAN_URLS = True` в tools/build_site.py и пересоберите — ссылки станут вида `/matrasy/matras-zevs/`.
- **Индексация.** Демо закрыто от поисковиков (`NOINDEX = True`: meta robots + robots.txt), чтобы не дублировать tmvo.ru. На рабочем домене — `NOINDEX = False`, sitemap.xml генерируется автоматически.
